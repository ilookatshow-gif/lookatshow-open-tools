# Как Lookatshow связывает задачи маркетинга и ИИ-агентов

[Каталог](README.ru.md) · [Практический вход](START-HERE.md) · [English summary](#english-summary)

Работа начинается с задачи компании, а не с выбора модели. Например: «Проверь выгрузку рекламных площадок и объясни, какие строки надо изучить». Для такого задания нужны данные, правила расчёта и проверка ответа. Название нейросети не заменяет ни одного из этих условий.

## Пять шагов одного сценария

| Шаг | Общий процесс | Пример с direct-report-audit |
|---|---|---|
| 1. Context / контекст | Описать продукт, источники, период, цель и границы действий | Одна нормализованная выгрузка, единая валюта и модель атрибуции; рекламу не менять |
| 2. Task / задача | Назвать вход, пороги и критерий готовности | Сложить строки по площадкам, посчитать CPC/CPA, вернуть причины ручной проверки |
| 3. Tools / инструменты | Запустить конкретный инструмент на выбранном входе | Локальная Python CLI-команда, без API кабинета |
| 4. Readback / проверка | Сверить результат с исходником и проверить ограничения | Проверить суммы, synthetic flag, пороги и причины; учесть задержку атрибуции |
| 5. Next step / следующий шаг | Зафиксировать решение, ответственного и следующую проверку | Передать кандидатов специалисту; сверить трекинг и качество лидов, а не отключать всё автоматически |

Этот порядок подходит исследованию конкурентов или разбору CRM, но сам по себе не создаёт интеграции. Каждый сценарий требует своего входа, инструмента и проверки.

## Ядро, модуль, skill и каталог

| Часть | Для чего она нужна | Что здесь доступно |
|---|---|---|
| Каталог `lookatshow-open-tools` | Найти рабочую задачу, версию, пример и путь к внедрению | Документация и CATALOG.json; никаких подключений при открытии README |
| Открытый модуль | Выполнить отдельную полезную работу | direct-report-audit v0.1.0, offline CLI, MIT |
| Companion skill | Объяснить агенту, когда и как использовать модуль | Инструкция внутри репозитория модуля; её регистрация зависит от клиента |
| MCP-подключение | Предоставить host'у инструменты через MCP | Не входит в direct-report-audit; CLI не выдаём за MCP-сервер |
| Ядро системы | Объединить контекст компании, конфигурацию, память, процессы и эксплуатацию | Отдельная поставка; каталог не устанавливает ядро и не включает его исходники |

Открытые модули работают без покупки ядра. Они не меняют его конфигурацию и не наследуют доступы других подключений. Платное продолжение может быть обучением команды или отдельным проектом внедрения; это разные услуги.

## Независимость от модели

Модули опираются на явные входы и выходы. Для текущего CLI нужны Python 3.9+ и возможность запустить локальную команду. Рабочий JSON не содержит повторной рекламы; агент может читать его и объяснять результат человеку.

Готовые prompts рассчитаны на Codex и Claude Code. Другие hosts проверяются отдельно: командой doctor, учебным примером и нужным пользователю сценарием. Общий протокол работы не означает проверенную совместимость всех моделей, MCP-клиентов или операционных систем.

## Что проверяем перед действием

Агент получает только нужные ему данные и права. Вызов команды ещё не подтверждает результат: сначала читаем JSON или квитанцию, затем проверяем состояние объекта. При неизвестном исходе внешней записи сначала выясняем, что произошло, а не повторяем действие вслепую.

У текущего модуля внешних записей нет. Рекламные расходы, отправка сообщений и изменения CRM могут появиться только в отдельно подключённых сценариях с выбранными пользователем границами. Ни установка модуля, ни чтение этой схемы таких действий не разрешают.

Учебные примеры вымышленные. У локальной утилиты нет сетевой передачи; у облачного агента действуют правила его провайдера. Реальные отчёты и клиентские данные не публикуются в GitHub.

## Развитие

Следующий `competitor-offer-radar` подготовлен локально, но ещё не опубликован. Он сравнивает два предоставленных снимка, не собирает сайты.

CRM и email требуют отдельных интеграций и своих проверок; сейчас это roadmap открытых модулей. Готовую связь нескольких компонентов показываем только после воспроизводимого сценария, а не по списку названий.

## English summary

Lookatshow uses five steps: context, task, tools, readback and next step. A task has selected input, action boundaries and a completion criterion. Tool output is checked before it becomes a business decision.

This catalog links standalone modules; it doesn't install the core. The current release is an offline Python CLI with companion agent instructions, not an MCP server. The core is a separate delivery for shared context, configuration and workflows. Free modules don't require it.

Model independence is a design principle, not a universal host support claim. Check your host with doctor and the synthetic example. Live accounts and external actions need separate access and user-selected scope.
